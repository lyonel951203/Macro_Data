# 三来源静默离线解析流程

当前轮次：20260912_001729。NBS 1068篇、PBOC 214篇、SAFE 319篇各一个隐藏后台工作进程，共1601篇；每篇独立子进程，90秒超时后记录并继续下一篇。没有网络请求、模型API调用或主库写入。无需保持VS Code打开，但电脑须保持运行、不休眠。

进度每5秒刷新到当前轮次latest.md，单篇候选和结果立即落盘；一轮结束汇总articles.csv、failed_articles.csv、failure_groups.csv和unverified_candidates.parquet。PARSED_CANDIDATES只表示旧解析器产生候选，不表示字段齐全或审核通过。

失败日志包括错误类型、完整traceback、URL与文档目录；NO_ROWS同样列为待查。磁盘无法写入等工作进程级故障另存fatal.json并显示WORKER_FAILED，不伪装为完成。单篇格式错误与超时不终止来源队列。

迭代步骤：
1. 当前全量轮次完成，按错误类型和文档格式分组分析。
2. 修改相应解析器并测试，创建新轮次，只重试FAILED、TIMEOUT和NO_ROWS：powershell -File scripts/start_archive_parsing.ps1 -RetryFrom E:\Macro_Data\reports\v2\archive_parse_runs\20260912_001729
3. 结合字段真实月份缺口检查成功稿是否漏提取；这类不能仅靠失败重跑覆盖，需要针对对应成功原稿另行回放核验。
4. 少数特殊文档最后人工（模型）读取；保留原句、单位、统计期和发布日期证据，再走独立核验、隔离试入和正式入库。

修复前先等当前轮次结束，避免运行中变更解析器；新轮次保存代码指纹和输入清单，旧轮次证据保留。相同代码及同一run可断点续跑，已完成文档跳过。代码变更必须创建新run。脚本本身不会自动修改代码，也不会无条件循环重试同一错误；后续规则修复和少数文档阅读仍需要模型参与。

本轮主要执行现有通用解析器，对此前专用审核脚本已入库的数据可能仍报错。因此候选、失败数量需与主库及既有审核批次对账，不视为新的有效数据或未经处理总量。
